## Diseño

- Acción: tres componentes continuas en `[-1,1]`, transformadas por el motor a velocidades solicitadas de bomba en `[0.6,1.0]`.
- Observación: vector observable de 15 variables; no se entrega `evaluation_truth` a la política.
- Entrenamiento: `MlpPolicy` PPO con red `[64,64]`, `gamma=0.99`, `gae_lambda=0.95`, `clip_range=0.2`, `learning_rate=3e-4`, `n_steps=256`, `batch_size=64` por defecto. Parámetros de referencia, no optimizados.
- Normalización: `VecNormalize` ajusta observaciones durante entrenamiento; `norm_reward=False` conserva la escala de recompensa S2.10 en UM. En inferencia, los estadísticos se congelan y se cargan del checkpoint.
- Semillas: entrenamiento 10000–10999, validación 20000–20031, prueba 30000–30031. El entorno de entrenamiento las recorre cíclicamente. Son particiones por semilla, no una prueba formal de independencia de los escenarios.
- Persistencia: `ppo_model.zip`, `normalization.pkl`, `metadata.json`, `rollouts.json`.
- Evaluación: por defecto 32 escenarios pareados contra `constant`, `demand_feedback` y `health_robust`; CSV con retorno, costos, energía, suministro, intervenciones y terminaciones.
- Seguridad: la capa de seguridad existente permanece activa. Reportar por separado la acción solicitada y ejecutada; la evaluación registra la distancia de intervención.

## Instalación

En Python 3.12, desde la raíz del proyecto:

```bash
python -m pip install -e '.[dev,ui,ppo]'
python -m pytest -q
```

## Entrenamiento piloto

```bash
python -m hydro_lab.ppo_s211 train --output resultados/s211_ppo_piloto --timesteps 4096
```

`4096` pasos es una **prueba de integración**, no un entrenamiento suficiente para afirmar aprendizaje. En la configuración por defecto, el entrenamiento usa una sola instancia del entorno y puede requerir tiempo de cómputo considerable.

## Evaluación (solo después de entrenar)

```bash
python -m hydro_lab.ppo_s211 evaluate --checkpoint resultados/s211_ppo_piloto --split validation
```

Produce `evaluation_validation.csv` en el directorio del checkpoint. Reservar `--split test` para después de fijar hiperparámetros y seleccionar el modelo; no usar el conjunto de prueba para ajustar PPO.

2. Se requiere entrenar con varias semillas y comparar con intervalos o distribución de diferencias pareadas antes de afirmar superioridad.
3. El evaluador de S2.11 emplea un horizonte de 96 pasos; si se entrena con otro horizonte, deberá ajustarse el evaluador.
4. Los checkpoints usan serialización de bibliotecas Python; **cargar únicamente archivos generados por fuentes confiables**.
5. No se modifica el manual de usuario ni se publican resultados ficticios.
6. La integración con Control Center, gráficos de aprendizaje y pruebas de generalización fuera de distribución corresponde a incrementos posteriores.
