# Hydro-Lab S2.11 — Incremento 04 / G0.1

**Objeto:** registro de episodios reales durante entrenamiento PPO, diagnósticos de optimización y evaluación periódica independiente sobre semillas reservadas.

## Alcance

Incremento **aditivo**. Se instala `src/hydro_lab/s211_train04.py` y `tests/test_s211_train04.py`; no se modifica `ppo_s211.py`, `agents.py`, la física hidráulica, la recompensa S2.10, ni los experimentos anteriores. Requiere las dependencias PPO del incremento 02.

El entrenamiento envuelve `SeedCycleEnv` en `Monitor` para capturar retornos acumulados y longitudes de episodios **terminados**; la ausencia de episodios terminados no se transforma en valores ficticios. Cada episodio registrado conserva su número de paso global y promedio móvil de los últimos 20 episodios terminados.

La evaluación periódica utiliza semillas 20000–20031, disjuntas de entrenamiento 10000–10999, con inferencia determinista. Las observaciones se normalizan con los momentos del entrenamiento, congelados temporalmente durante evaluación. Se restauran después. No se entrena sobre escenarios de validación. Las semillas de prueba 30000–30031 quedan reservadas para evaluación final.

## Salidas

En una **carpeta de salida nueva**, se escriben:

- `ppo_model.zip`, `normalization.pkl`, `metadata.json`: checkpoint compatible con `hydro_lab.ppo_s211 evaluate`.
- `episodes_training.csv`: paso global, número de episodio terminado, retorno en UM, longitud y media móvil de hasta 20 episodios.
- `validation_during_training.csv`: retorno, pasos, terminación anticipada, déficit, energía e intervenciones por escenario fijo y punto de evaluación.
- `ppo_diagnostics.csv`: divergencia KL aproximada, fracción recortada, entropía, pérdidas de valor y política, varianza explicada, cuando SB3 las expone. Se etiquetan con el paso de la actualización que las produjo.

**Limitaciones:** los retornos por episodio de entrenamiento y validación no son intercambiables; los primeros se obtienen de políticas estocásticas durante exploración, los segundos de políticas deterministas. Las métricas de PPO son diagnósticas, no pruebas de convergencia. Las evaluaciones periódicas sirven para desarrollo y selección; la partición `test` permanece sin utilizar. Esta versión no implementa inferencia estadística entre semillas ni corrige todavía la coincidencia de controladores `health_robust` y `demand_feedback`.

## Ejecución piloto

```bash
python -m hydro_lab.s211_train04 \
  --output resultados/s211_ppo_instrumentado_04 \
  --timesteps 4096 \
  --eval-every 1024 \
  --validation-count 8
```

Después:

```bash
python -m hydro_lab.ppo_s211 evaluate \
  --checkpoint resultados/s211_ppo_instrumentado_04 \
  --split validation
```

No reutilizar la carpeta `s211_ppo_piloto` ni sobrescribir checkpoints anteriores. La evaluación periódica puede hacer que esta ejecución tarde considerablemente más que la anterior.

## Criterios de aceptación

1. Las pruebas anteriores continúan pasando.
2. Se crean los seis archivos previstos y `metadata.json` informa `episodes_observed`.
3. `validation_during_training.csv` contiene 8 escenarios por evaluación realizada.
4. `episodes_training.csv` contiene retornos numéricos de episodios terminados, o solamente encabezado si ninguno concluyó; nunca rellenar valores ausentes con cero.
5. El checkpoint carga con el evaluador S2.11 existente.
