# S2.9 — Validación científica de observación activa

## Pregunta experimental
¿En qué condiciones la información de inspecciones robóticas modifica las acciones de control y produce un beneficio hidráulico que excede los costos de inspección?

## Diseño
Se mantienen las ecuaciones hidráulicas y el filtro de seguridad S2.8. Para cada semilla se ejecutan cuatro brazos: retroalimentación de demanda sin/con robot, y control sensible a salud sin/con robot. Se usan las mismas realizaciones exógenas por semilla y régimen. Las trayectorias de estado divergen legítimamente cuando las acciones cambian. La política de inspección `uncertainty` es heurística, no óptima.

Regímenes **predeclarados**:
1. `baseline`: escenario original S2.8.
2. `degraded`: salud inicial (.75,.90,.90).
3. `accelerated_wear`: igual a degraded, con choque exógeno adicional de -0.001 por paso sobre P0. Este choque es hipotético y no representa desgaste medido en Ecopetrol.

## Variables y contrastes
`net_reward_um` ya descuenta costos robóticos. `hydraulic_reward_um = net_reward_um + robot_cost_um`. Para cada semilla se calculan diferencias pareadas con robot menos sin robot. Se informa el número de pasos con acciones solicitadas diferentes (evidencia de sensibilidad del controlador, no prueba de utilidad). Se calcula también diferencia-en-diferencias entre controladores. Los intervalos aproximados normales del 95 % son descriptivos, no ajustados por multiplicidad y poco fiables para eventos raros.

## Reproducir en Mac
Desde la carpeta `hydro-lab-g2` con el entorno `hydro-lab` activo:

```bash
python -m pytest -v
python examples/validate_s29.py --seeds 20 --output results/s29_run1
```

Genera JSON (detalle), CSV (episodios), y Markdown (síntesis). Si el directorio ya contiene esos archivos, se detiene para preservar el histórico. Cambia `--output` para una nueva generación. Con 20 semillas, 3 regímenes y 4 brazos se ejecutan hasta 240 episodios; puede tardar, dependiendo del equipo.

## Límites
Este diseño no prueba optimalidad ni seguridad industrial, ni garantiza beneficio económico. El desgaste acelerado es una hipótesis de estrés; las fallas son las del simulador. El controlador sensible a salud usa un heurístico con redistribución de velocidades, no una solución de control óptimo. Antes de trasladar conclusiones a una instalación real se requieren parámetros y modelos de fallas calibrados y un análisis de sensibilidad adicional.
