# Hydro-Lab S2.11 — Incremento 05 / G0.1

## Objetivo

Diagnosticar fallos hidráulicos por escenario y separar dos fuentes de variación: **escenarios hidráulicos** y **semillas de entrenamiento PPO**. El incremento no modifica la física, la recompensa ni los módulos anteriores.

## Diseño

El evaluador registra, por combinación de semilla de entrenamiento y escenario, retorno en UM, terminación anticipada, pasos, demanda servida y no servida, energía, intervenciones y desglose de costos. La comparación PPO–controlador se realiza **pareada dentro de cada escenario** y de cada réplica de entrenamiento. Se calcula un resumen por semilla de entrenamiento; nunca se tratan todas las filas escenario × réplica como si fueran réplicas de entrenamiento independientes.

Se exporta una estimación exploratoria de variabilidad entre semillas de entrenamiento. El intervalo normal aproximado de 95 % es únicamente descriptivo, especialmente con tres semillas; **no constituye inferencia confirmatoria**. No se afirma seguridad hidráulica por tener un buen retorno promedio. El conjunto `test` debe reservarse para una evaluación final tras fijar el procedimiento y seleccionar la política en validación.

## Ejecución recomendada, por etapas

Primero probar la herramienta **sin volver a entrenar**, con el checkpoint del incremento 04:

```bash
python -m hydro_lab.s211_study05 diagnose \
  --checkpoint resultados/s211_ppo_instrumentado_04 \
  --output resultados/s211_diagnostico_05_piloto \
  --split validation \
  --scenario-count 8
```

Una vez revisado el diagnóstico, realizar un ensayo de replicación (piloto, **no estudio definitivo**):

```bash
python -m hydro_lab.s211_study05 train-replicates \
  --output resultados/s211_replicas_05 \
  --seeds 41 42 43 \
  --timesteps 4096 \
  --eval-every 1024 \
  --validation-count 8
```

Después evaluar los tres checkpoints en los mismos escenarios:

```bash
python -m hydro_lab.s211_study05 diagnose \
  --checkpoint resultados/s211_replicas_05/seed_41 resultados/s211_replicas_05/seed_42 resultados/s211_replicas_05/seed_43 \
  --output resultados/s211_diagnostico_05_replicas \
  --split validation \
  --scenario-count 8
```

Los directorios de salida deben estar vacíos o no existir. El programa se niega a sobrescribir resultados.

## Interpretación y límites

- `episodes.csv`: datos desagregados por réplica, escenario y política.
- `paired.csv`: diferencias PPO menos controlador; retornos mayores son mejores; déficits y energía menores suelen ser mejores.
- `summary_by_seed.csv`: estadísticas por política y semilla de entrenamiento.
- `between_seed_variability.csv`: variación entre promedios pareados por semilla de entrenamiento, con intervalo normal aproximado solo descriptivo.
- `report.json`: procedencia, particiones y advertencias.

**Diagnóstico pendiente:** la identidad exacta de `health_robust` y `demand_feedback` observada previamente requiere revisar su implementación y la activación efectiva de sus mecanismos. El incremento 05 conserva ambos como referencias, pero no concluye que sean algoritmos equivalentes.

**Criterio de cierre:** pruebas de regresión aprobadas, diagnóstico piloto ejecutado, salidas inspeccionadas, sin conclusiones de robustez hasta fijar umbrales hidráulicos y un protocolo inferencial definitivo.
